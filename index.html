重点：无源蜂鸣器必须由 交变的 PWM 方波驱动才会持续振动发声；只给一个恒定高电平只有“嗒”一声，甚至一直直流导通。所以“停止”不能只是不翻转电平，必须 关闭 PWM 通道并把引脚固定为低电平。

手机「手动添加网络」逐项怎么填（安全性 / 隐私 / 隐藏的网络）

依据固件实际配置：WPA/WPA2-PSK 混合加密 · SSID 广播不隐藏 · 仅 2.4 GHz CH6 · 只有 AP + DHCP 无外网出口
安全性怎么选选 WPA/WPA2-Personal（有的手机写作 WPA2-PSK / WPA/WPA2-PSK）。固件用的是 WIFI_SEC_TYPE_WPA2_WPA_PSK_MIX。别选 WPA3 / SAE别选无
隐私怎么选选 使用设备 MAC。固件不限制 MAC，随机 MAC 也能连，但设备 MAC 便于和串口打印的 MAC 对照，且避免个别手机在 WPA/WPA2 混合下反复认证失败。
隐藏的网络怎么选选 否 / 不勾选。固件 hidden_ssid_flag=1，服务层转成 ssid_hidden=0，即 SSID 正常广播；勾了"是"反而会连不上。
网络名称 / SSID
H
单个大写字母，区分大小写；不要加空格、引号或中文全角字符。
密码
12345678
8 位纯数字，与 WIFI_SOFTAP_PASSWORD 一致；勾选"显示密码"核对一遍。
安全性
WPA/WPA2-Personal
等价写法：WPA2-PSK、WPA/WPA2-PSK、WPA2-个人。WPA3-Personal / SAE / 开放 / 企业级 EAP 均不匹配
隐私（Android 12+）
使用设备 MAC
若只有"随机 MAC"也可连接；连上后可在 WLAN 详情里看到实际 MAC，与串口 STA JOIN MAC= 对比。
隐藏的网络
否 / 关闭
保持默认关闭即可；找不到列表时再点"添加网络"，不是因为热点被隐藏。
IP 设置 / 代理
DHCP（动态） / 无
固件启动 netifapi_dhcps_start()，手机应自动拿到 192.168.63.x、网关 192.168.63.1。不要设静态 IP
频段 / 信道
2.4 GHz / CH6
核心板只有 2.4 GHz；部分手机"添加网络"里有频段选项时选 2.4 GHz，关掉 5 GHz 优先和 WLAN+ 智能切换。
按流量计费
不视为计量 / 无
默认即可，避免系统因为"计量网络"限制连接。
弹出「无互联网」
保持连接 / 仍然连接
这是正常现象：核心板只是 AP + DHCP，没有接外网。手机会提示"无法访问互联网"，务必选保持连接，别点"切换网络"；建议先临时关闭移动数据。
填完点保存 / 连接后怎么确认成功：手机 WLAN 详情显示「已连接」、IP 形如 192.168.63.3、网关 192.168.63.1；同时串口出现 [EVENT] STA JOIN → ****** 手机连接热点成功 / PHONE CONNECTED HOTSPOT SUCCESS ****** → [DHCP] phone ... IP=192.168.63.3 → RESULT / 实训验收。
若保存后一直"正在获取 IP 地址"或反复断开：先长按热点「忘记网络」再按上表重填一次；确认串口已有 SSID "H" is now broadcasting 与 SoftAp start success.（没有则说明是板卡侧问题，见下方排障卡）；关掉移动数据与 WLAN+；换另一台手机交叉验证。

实测反馈 · 烧录之后没有生成网络 / 手机搜不到热点

排障：热点「H」为什么没出现 已修复并重编译

先查固件：当前 ws63-liteos-app.bin 里确实含有 [WIFIAP]、WiFiSoftAPTask、12345678 和 RESULT 段，CONFIG_SAMPLE_SUPPORT_WIFIAP 也仍然启用 —— 样例没有被裁掉。问题集中在「启动任务被卡住 / 热点被自己关掉 / 烧录包不含 NV」。

原因 1 · 无限死等旧版 while (wifi_is_wifi_inited() == 0) 没有超时
原因 2 · 附属失败即关热点netif / DHCP 一失败就 wifi_softap_disable()
原因 3 · 没有明确 SSID 广播配置未显式设置 hidden_ssid_flag=1，enable 也无重试
原因 4 · 烧录包不对只烧单个 .bin 或 load_only.fwpkg，缺 NV 射频校准数据
关键依据：本工程 ws63_liteos_app.config 中 # CONFIG_ENABLE_WIFI_SAMPLE is not set， 系统启动链里没有任何地方调用 wifi_init()（只有 AT 命令 AT+WIFIINIT 与 PM 复位会调）。 因此 wifi_is_wifi_inited() 一旦迟迟不置 1，旧版任务就永远卡在第一行日志之后，SoftAP 根本不会被开启。 vendor 实验指导原版用的是固定 5 s 延时，不存在这个死等，这是上一轮改造引入的回归。
修复 115 s 有限等待，超时自动调用 wifi_init() 兜底
修复 2显式 hidden_ssid_flag=1（不隐藏）+ enable 失败重试 3 次
修复 3netif / DHCP 失败只告警，保持热点开启
修复 4每步打印 [DIAG] 返回码，回调注册失败不再阻断

按串口最后停在哪一行定位（脚本结束会自动给出同样结论）：
  1. 完全没有 [WIFIAP] 行 → 固件没跑：烧错包 / 烧完没再按 RESET / 串口选错或波特率不对 / IDE 重新 Kconfig 后取消勾选样例没重编译。
  2. 只有 Start 与 BOOT CHECK → WiFi host 未就绪：改烧 *_all.fwpkg（含 ws63_all_nv.bin），重新上电。
  3. 有 WiFi init OK 但 wifi_softap_enable ret 非 0 或出现 FATAL → WiFi device 侧 / NV 校准异常：重烧 all.fwpkg，必要时 rebuild。
  4. 有 SSID "H" is now broadcasting 但手机看不到 → 手机侧手动「添加网络」H / 12345678 / WPA2-PSK，只搜 2.4 GHz，在列表底部找被折叠的「无互联网」热点，关掉 WLAN+ 智能切换。
  5. 有 SoftAp start success 但没有 STA JOIN → 密码或加密方式不匹配，或手机自动切回移动数据（先关移动数据再连）。
