wifiap 实训 · 预期串口日志（v4 根因修复版 BUILD=v4-wifiinit-fix）
======================================================================
说明：以下逐行对应 softap_sample.c 中 PRINT 语句的输出格式，由脚本回放生成，
      不是真实板卡采集数据；MAC / IP / RSSI 随实际手机变化。
      真实采集：python wifiap_serial_monitor.py --diag

【为什么需要 v4】wifi_softap_enable() -> wifi_get_enable_status() 要求
uapi_wifi_get_init_status()==1；本工程启动链没有任何 wifi_init() 调用，
所以 vendor 原版固定 5 s 后直接 enable 必然失败、热点不会广播。
v4 在开机 5 s 后主动调用 wifi_init()，随后持续重试 enable。

---- 异常分支 A：wifi_init() 一直失败 ----
[WIFIAP] [DIAG] wifi_init() try 1/10 ret=-1 status=0
[WIFIAP] [DIAG] wifi_init() try 10/10 ret=-1 status=0
[WIFIAP] FATAL: wifi_init() failed after 10 tries.
[WIFIAP] HINT: 1) 烧 *_all.fwpkg 2) 烧完按 RESET 3) 串口发 AT+WIFIINIT 4) 检查 NV 校准数据
处理：重新上电；确认烧的是 *_all.fwpkg（含 ws63_all_nv.bin）；在串口助手手动发 AT+WIFIINIT；
      v4 的 enable 持续重试会自动接上，不需要重新烧录。

---- 异常分支 B：init 成功但 enable 失败 ----
[WIFIAP] [DIAG] wifi_init() try 1/10 ret=0 status=1
[WIFIAP] [DIAG] wifi_softap_enable try 1/60 ret=-1 (init_status=1)
[WIFIAP] HINT: ret!=0 可用串口发送 AT+WIFIINIT；本任务每 2000 ms 自动重试一次
处理：等满 120 s 重试窗口；多为 WiFi device 侧 / NV 校准 / 信道冲突，重烧 all.fwpkg 并重新上电。

---- 异常分支 C：热点已起但手机没连 ----
[WIFIAP] SoftAP enabled OK. SSID "H" is now broadcasting.
[WIFIAP] SoftAp start success.
[WIFIAP] [DIAG] heartbeat: init_status=1, netif=ap0-ready, stations=0
处理：此时才是手机侧问题。手动添加网络：SSID 精确填 H、密码 12345678、
      安全性 WPA/WPA2-Personal、隐私使用设备 MAC、隐藏网络选否、IP 设置 DHCP；
      只搜 2.4 GHz，关 WLAN+ 与移动数据；弹出「无互联网」时选「保持连接」。

---- 排障对照表 ----
1) 完全没有 [WIFIAP] 行            -> 固件没跑：烧错包 / 没按 RESET / COM 口或波特率不对
2) 没有 BUILD=v4-wifiinit-fix      -> 板子里还是旧固件，重烧本次 all.fwpkg
3) wifi_init() try ... status=0    -> WiFi device 未就绪：重新上电 / AT+WIFIINIT / 重烧 all.fwpkg
4) wifi_softap_enable try ... !=0  -> device / NV / 信道问题，等满 120 s 再判定
5) 有 is now broadcasting 但搜不到 -> 手机侧：2.4 GHz、关闭 WLAN+、列表底部找「无互联网」热点
6) 有 SoftAp start success 无 JOIN -> 密码/加密不匹配，或手机自动切回移动数据
